# TM-Sim: локальная программа оценки сходства товарных знаков

Программа работает полностью на вашем компьютере: веб-интерфейс в браузере, база знаков в файле SQLite и локальная ИИ-модель через Ollama. Данные никуда не отправляются.

## Что умеет

- **Сравнение двух знаков** (словесных, изобразительных, комбинированных) по критериям Казпатента. Выдаёт процент риска смешения, степень сходства и разбор по каждому признаку.
- **Поиск по базе**: заявляемое обозначение сравнивается со всеми зарегистрированными знаками в тех же и смежных классах МКТУ, результаты отсортированы по риску.
- **Импорт электронного бюллетеня Казпатента** (сохранённая страница ebulletin.kazpatent.kz): берётся только раздел «Товарные знаки», названия знаков распознаются с изображений. Поддерживаются также PDF, TXT, CSV, JSON и XLSX.
- **ИИ-помощник** ведёт диалог, сам ищет по базе, сравнивает знаки, проверяет абсолютные основания и объясняет результат.
- **Предварительная проверка охраноспособности**: госсимволика, международные организации, географические названия, алкоголь вне 32/33 класса, наименования мест происхождения, описательные слова, мораль, объекты культурного наследия, 1–2 буквы или только цифры.
- **Подбор весов по реальным решениям**: отмечаете пары «Казпатент признал сходными / не сходными», программа подбирает веса и порог.

## Установка (Windows)

1. Установите **Python 3.10+** с python.org и при установке отметьте «Add Python to PATH».
2. Установите **Ollama** с https://ollama.com и скачайте модели в командной строке:
   ```
   ollama pull qwen2.5:7b-instruct    # диалог и оценка смысла (~4.7 ГБ)
   ollama pull bge-m3                 # многоязычные эмбеддинги для смысла (~1.2 ГБ)
   ollama pull qwen2.5vl:7b           # необязательно: распознаёт текст на логотипах
   ```
   Для слабых компьютеров без видеокарты подойдёт `qwen2.5:3b-instruct`. Модель меняется на вкладке «Веса и настройки».
3. Запустите **run.bat**. При первом запуске он сам поставит зависимости, затем откроет браузер на http://127.0.0.1:8000.

На Linux и Mac то же самое делает `./run.sh`.

Нейросеть CLIP для изображений ставится по желанию: `.venv\Scripts\pip install sentence-transformers` (около 600 МБ). Без неё изображения сравниваются по форме, композиции и цвету.

Без Ollama программа тоже работает: фонетика, графика, изображения, классы и встроенный словарь смыслов считаются без ИИ. Недоступны только чат и смысловое сравнение с помощью LLM.

## Методика и веса

Казпатент перечисляет признаки сходства, но не публикует их веса. Ниже веса, которые предлагает программа. Все они редактируются в интерфейсе (`config/weights.json`).

### 1. Словесный элемент

| Признак | Вес | Из чего складывается |
|---|---|---|
| Звуковое (фонетическое) | **45%** | совпадение звуков 35%, восприятие на слух с редукцией гласных 20%, совпадение начала 20%, согласный «скелет» 15%, число слогов и длина 10%; плюс вхождение одного обозначения в другое |
| Смысловое (семантическое) | **30%** | встроенный словарь понятий рус/каз/англ, эмбеддинги bge-m3, оценка LLM с обоснованием. Для фантазийных слов критерий исключается из расчёта |
| Графическое (написание) | **25%** | похожие по начертанию буквы 50%, тип алфавита 20%, длина 15%, структура и регистр 15% |

На практике сходство признают и **по одному признаку**, поэтому итог считается не простым средним:

```
S_слово = 0.6 · max(S_ф, S_с, 0.9·S_г) + 0.4 · (взвешенное среднее)
```

Коэффициент 0.6 (β) задаётся в настройках.

- **Тождество** (отличие только падежом, числом, уменьшительной формой, наличием или отсутствием предлога) даёт 100%.
- **Сильные и слабые элементы.** Словосочетания и слитные написания (SuperFood → super + food) разбираются на элементы. Описательные, хвалебные, географические слова и организационно-правовые формы считаются слабыми. Сравнение по сильным элементам может стать решающим.
- **Транслитерация.** Кириллица (включая казахские буквы ә, ғ, қ, ң, ө, ұ, ү, һ, і), латиница и казахская латиница приводятся к единой транскрипции, поэтому Altyn и Алтын звучат одинаково.

### 2. Изобразительный элемент

С CLIP: общее зрительное впечатление 45%, форма и контур 30%, цвет 15%, композиция 10%. Без CLIP: форма 55%, композиция 25%, цвет 20%. Зеркальное отражение и смена масштаба тоже распознаются.

### 3. Комбинированный знак

```
S_знак = max(0.65·S_слово + 0.35·S_изобр, 0.85·S_слово, 0.75·S_изобр)
```

Словесный элемент обычно сильнее изображения: его запоминают и произносят.

### 4. Однородность товаров и услуг (МКТУ)

Тот же класс даёт 1.0, смежные классы 0.6 (группы в `tmsim/nice.py`, например 29/30/31/32/43 или 3/5/44), 35 класс (торговля) против товаров 0.4, неоднородные классы 0.1. Если указаны перечни товаров, учитывается и их пересечение.

```
Риск смешения = S_знак · (1 − λ + λ·K),  λ = 0.5
```

### 5. Пороги

Высокая степень сходства от 80%, средняя от 62%, низкая от 45%.

> Результат — расчётная оценка по предложенным весам, а не заключение Казпатента.

## Импорт бюллетеней

**Основной способ: электронный бюллетень Казпатента.**

1. Откройте https://ebulletin.kazpatent.kz, выберите год и нажмите [RU] у нужной даты.
2. Дождитесь, пока выпуск загрузится полностью, и нажмите **Ctrl+S**, тип «Веб-страница полностью».
3. Перетащите сохранённый файл `.htm` на вкладку «База знаков».

Программа берёт из выпуска только раздел «Товарные знаки» (номер регистрации и заявки, даты, владелец, изображение, неохраняемые элементы, цвета, классы МКТУ и перечень товаров). Изобретения, полезные модели, образцы, извещения и указатели пропускаются. Выпуск 2026-01-09 (169 знаков) загружается примерно за 5 секунд.

**Названия знаков.** В бюллетене обозначение (540) дано только картинкой, поэтому слово на ней нужно распознать:
- для выпуска 2026-01-09 названия и описания изображений всех 169 знаков уже подготовлены (`seed/bulletin_2026-01-09.json`);
- для остальных выпусков название читает локальная vision-модель (`ollama pull qwen2.5vl:7b`), она же кратко описывает рисунок: «кобра», «лев с короной»;
- если модель не установлена, кнопка «Распознать названия» на вкладке «База знаков» запустит распознавание позже, а любое название можно исправить вручную щелчком по нему в таблице.

Описание рисунка участвует в сравнении: слово «Кобра» будет сходно по смыслу со знаком, где нарисована кобра.

PDF-бюллетени и таблицы тоже поддерживаются. Записи разбираются по кодам ИНИД, а в таблицах распознаются колонки: «Номер регистрации», «Номер заявки», «Обозначение», «Классы», «Товары», «Владелец», «Дата регистрации», «Изображение» (путь к файлу) и коды 111, 210, 540, 511, 732.

## Структура

```
tmsim/translit.py    транслитерация и фонетические ключи
tmsim/text_sim.py    фонетика, графика написания, тождество, сильные/слабые элементы
tmsim/semantic.py    смысловое сходство (словарь, эмбеддинги, LLM)
tmsim/image_sim.py   сравнение изображений
tmsim/nice.py        классы МКТУ и однородность
tmsim/scoring.py     итоговая формула
tmsim/absolute.py    проверка абсолютных оснований
tmsim/ebulletin.py   разбор электронного бюллетеня (раздел «Товарные знаки»)
tmsim/bulletin.py    парсер PDF/таблиц по кодам ИНИД
tmsim/importer.py    импорт и распознавание названий
seed/                готовые названия знаков по номерам регистрации
tmsim/agent.py       ИИ-помощник с инструментами
tmsim/main.py        веб-сервер (FastAPI), интерфейс в tmsim/static
config/weights.json  веса;  config/settings.json  модели и адреса
data/                база marks.sqlite3, изображения, загруженные бюллетени
```

Тесты запускаются командой `python -m pytest tests`.
